# Plus AI 비밀번호 접근 V1

- [v] AI Gen 버튼 진입 시 비밀번호 확인 UI를 먼저 표시한다. 서버가 승인하기 전에는 AI 조작 UI를 표시하지 않는다.
- [v] 서버 환경변수 `PASSWORD`는 평문 대신 `scrypt$salt$hash` 형식의 검증값으로 저장한다. 기존 `AI_ACCESS_TOKEN` 방식은 대체한다.
- [v] `npm run password:hash`로 비밀번호를 숨김 입력하고 salt가 다른 해시를 생성할 수 있도록 한다. 출력값은 배포 환경변수에 넣고 실제 UI에서는 원래 비밀번호를 입력한다.
- [v] 서버에서 상수 시간 비교로 검증한 뒤 서명된 1시간 인증 쿠키를 발급한다. 기능 조회·전사 API도 인증을 검사하여 UI 우회를 차단한다.
- [v] 쿠키는 HttpOnly·SameSite=Strict, 운영에서는 Secure로 설정한다. 비밀번호 변경 시 기존 서명을 무효화한다. 프런트 저장소·프로젝트·응답·로그에 비밀번호나 서버 해시를 넣지 않는다.
- [v] 로그인 요청 크기·대기 시간·빈도·동시 실행을 제한한다. 운영의 기존 공유 요청 제한도 유지한다.
- [v] 운영에서 PASSWORD 미설정·잘못된 해시는 접근을 차단한다. 개발 모드에서만 PASSWORD가 없을 때 로컬 인증을 생략한다.

비밀번호 선택은 사용자 로컬 터미널에서 수행하며 `your_password_here`를 공용 기본 비밀번호로 자동 설정하지 않는다. 실제 비밀번호·배포 환경변수는 이번 코드 변경으로 임의 설정하지 않는다. 브라우저·실제 AI 요청 재검증은 생략한다.

프런트·서버 타입 검사를 통과했다. 필수 인증 확인으로 `npx vitest run tests/ai-password.test.ts`의 비밀번호 검증·쿠키 위변조/해시 변경·미인증 API 차단 3개 검사가 통과했다. 실제 사용자 비밀번호나 외부 AI API는 사용하지 않았다.
