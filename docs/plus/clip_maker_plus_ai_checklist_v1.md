# 클립메이커 플러스 AI 체크리스트 V1

## 목적과 완료 표기

AI Gen과 범용 AI API 연결 모듈의 기본 골격 및 첫 자동 자막 기능을 현재 편집기에 연결하기 위한 구현 순서다. 설계 기준은 [AI V2](./clip_maker_plus_ai_v2.md), [AI V3](./clip_maker_plus_ai_v3.md)이며 계층 경계는 V3를 따른다.

모든 항목은 `[ ]`로 시작하고 실제 구현 완료 시에만 `[v]`로 변경한다. 현재 표시는 아래 구현·확인 기록을 따른다. 문서 작성·기존 유사 코드 존재만으로 구현 완료 표시를 하지 않는다. 검증을 실행하지 않은 경우 성공으로 표시하지 않는다. 원본 `CHECKLIST.md`와 해시 파일은 변경하지 않는다.

1~4단계가 공용 호출 골격, 5~7단계가 AI Gen의 첫 기능 연결, 8단계가 배포·인수인계 범위다. 공용 골격만 완료한 상태를 자동 자막 전체 구현 완료로 보고하지 않는다.

## 현재 프로젝트와 연결 지점

현재 프런트엔드는 React·TypeScript·Vite이며 서버 진입점은 아직 없다. `src/app/App.tsx`는 모달·편집 잠금·히스토리 적용을 관리하고, `src/editor/Timeline.tsx`는 확장 버튼을 표시한다. `src/project/model.ts`의 `mediaLayout`은 합쳐진 영상의 원본 구간을 해석하며, `src/project/commands.ts`의 `replaceTimeline`으로 타임라인을 한 번에 교체할 수 있다.

기존 `modules/auto-caption`은 빈 자막 생성 기능이다. 이를 AI Gen으로 대체하거나 설정·결과를 공유하지 않는다. 기존 로컬 VAD·PCM 처리도 외부 전송이나 기존 기능 동작이 바뀌지 않는 범위에서만 재사용한다.

## 계층과 폴더 기준

| 위치 | 책임 |
| --- | --- |
| `modules/ai-api/shared/` | 공급자 중립적인 작업·요청·응답·오류 계약과 런타임 입력 검증 |
| `modules/ai-api/client/` | 브라우저에서 자체 백엔드로 요청하는 공용 클라이언트 |
| `modules/ai-api/server/` | 인증·제한·공급자 선택·공통 HTTP 처리·서버 설정 |
| `modules/ai-api/server/providers/` | DeepSeek 등 공급자별 인증·엔드포인트·응답 변환 |
| `modules/ai-gen/src/` | AI Gen 모달·작업 상태·로컬 음성 준비·임시 결과·자막 생성 계획 |
| `server/` | 일반 Node 서버의 실행·환경 파일 로딩·HTTP 진입 어댑터 |
| `api/` | Vercel 등 서버리스 배포용 얇은 진입 어댑터. 핵심 로직을 두지 않음 |
| `src/app/App.tsx` | AI Gen 열기·프로젝트 스냅샷·최종 적용 연결만 담당 |

공용 호출 모듈은 React·Project·Cue·타임라인 명령에 의존하지 않는다. AI Gen은 공급자 SDK·공급자 URL·키를 직접 다루지 않는다. 폴더명은 구현 기준이며 플랫폼별 어댑터의 파일 규칙만 해당 플랫폼에 맞출 수 있다.

## 1. 작업 범위와 기반 설정

- [v] **P01** 사용자에게 보이는 제품 타이틀·로고 텍스트·관련 메타데이터를 `Devianns Clip Maker Plus`로 통일한다. 기존 편집 데이터의 ID·스키마를 제품명 변경 때문에 바꾸지 않는다.
- [v] **P02** 위 폴더 경계를 만들고 브라우저·서버 타입 검사 설정을 분리한다. 현재 DOM 중심 `tsconfig.json`에 서버 전용 전역 타입을 무분별하게 섞지 않으며 새 모듈도 검사 범위에 포함한다.
- [v] **P03** 기존 개발·빌드 흐름을 유지하면서 프런트와 자체 API를 함께 실행할 개발 명령, 서버 빌드·시작 명령을 실제 구현에 맞게 추가한다. Vite 개발 프록시는 개발용으로 한정하고 배포 시에는 명시적인 자체 API 기준 주소를 사용한다.
- [v] **P04** 서버 설정 계약을 정의한다. 초기 비밀값은 `DEEPSEEK_API_KEY`, 공개 가능한 값은 자체 API 주소·사용 가능한 기능 정도로 제한한다. `.env.local`은 개발 서버에서만 로딩하며 배포는 서버 환경변수를 사용한다. 키를 `VITE_` 변수·프런트 코드·로그에 노출하지 않는다.

## 2. 공급자 중립 공통 계약

- [v] **C01** `operation`으로 구분하는 요청·응답 타입을 정의한다. 첫 작업은 `transcribe`이며, 향후 `generateText`도 별도 계약으로 추가할 수 있게 한다. 모든 작업을 자막 생성이나 단일 채팅 메시지 형식에 억지로 맞추지 않는다.
- [v] **C02** 전사 요청은 요청 ID, 음성 파일, 선택적 언어 힌트를 포함한다. 클립 ID·라인 번호·프로젝트 JSON은 공용 API가 필요로 하지 않는다. 음성 MIME·컨테이너·크기·길이는 서버 경계에서 검증한다.
- [v] **C03** 전사 결과는 요청 ID, 텍스트, 제공 가능한 음성 길이와 선택적 구간 정보를 반환한다. 공급자에게 없는 단어별 시간은 생성하지 않으며 길이 단위는 필드명으로 구분한다. 프로젝트 시간은 AI Gen 내부에서만 정수 마이크로초로 관리한다.
- [v] **C04** 공급자 인터페이스와 등록부를 정의한다. 공급자는 지원 작업·지원 입력·한도를 알리고, 작업별 실행 함수는 취소 신호를 받는다. 새 공급자는 어댑터 등록으로 추가하며 기존 AI Gen 내부에 공급자별 분기를 늘리지 않는다.
- [v] **C05** 서버가 공개 가능한 기능 정보를 제공하도록 한다. 설정 누락·지원하지 않는 작업은 실행 전에 알린다. 다른 공급자로 자동 대체하거나 원본을 임의 전송하지 않는다. 설정 존재 확인을 실제 API 사용 성공으로 표시하지 않는다.
- [v] **C06** 공통 오류 코드를 정의한다. 최소한 설정 누락·지원 불가·인증 실패·잘못된 입력·크기 초과·요청 제한·시간 초과·공급자 실패·잘못된 응답·취소를 구분하고 공급자 원문 응답·헤더·키를 사용자에게 그대로 노출하지 않는다.

## 3. AI API 연결 모듈과 DeepSeek 어댑터

- [v] **A01** 공용 HTTP 처리 함수는 표준 `Request → Promise<Response>` 계약으로 구현한다. 요청 검증·공급자 선택·응답 정규화는 이 계층에서 수행하며 특정 플랫폼 객체는 진입 어댑터에서만 변환한다.
- [v] **A02** 자체 API 경로를 기능 조회와 전사 호출로 나눈다. 예: `GET /api/ai/capabilities`, `POST /api/ai/transcribe`. 전사는 multipart 업로드를 사용하고 응답 JSON을 런타임 검증한다. 임의 원격 URL을 대신 가져오는 API는 만들지 않는다.
- [v] **A03** DeepSeek 전사 엔드포인트·인증·입력 형식·응답 계약을 구현 직전 공식 문서로 재확인한다. V2 조사 기준은 `/v1/tools/asr`, PCM16 WAV/Ogg Opus, 8MiB·120초, 텍스트·길이 응답이다. 실제 사용 계정의 권한과 문서상 지원을 구분한다.
- [v] **A04** DeepSeek 어댑터에서 서버 키로 호출하고 응답 텍스트·길이·형식을 검사한다. 빈 문자열 전사는 정상적인 결과로 구분한다. API 오류나 HTML 응답을 자막 텍스트로 사용하지 않는다.
- [v] **A05** 브라우저 클라이언트는 자체 백엔드만 호출하고 요청 ID·취소 신호·시간 초과를 처리한다. 공급자 키·인증 형식은 알지 못한다. 공개 API 주소만 설정할 수 있게 한다.
- [v] **A06** 과금 요청은 무제한 자동 재시도하지 않는다. 재시도 가능 오류를 표시하고 사용자가 실패 구간만 재시도할 수 있게 한다. 응답을 잃은 요청의 재시도는 중복 과금 가능성을 안내하며 지원되지 않는 멱등성을 보장하지 않는다.
- [v] **A07** 업로드 크기·작업 시간·동시 요청·한 작업의 구간 수에 명시적 상한과 backpressure를 둔다. 공급자와 배포 환경 중 더 작은 한도에 맞춰 제한하며 전체 영상·전체 PCM을 서버 메모리에 누적하지 않는다.
- [v] **A08** 공개 배포 시 서버 키를 사용하는 API에 인증·요청량 제한을 적용한다. 허용 출처 정책은 인증을 대신하지 않는다. 공급자·모델·기본 URL은 서버의 허용 목록으로 관리한다. 서버리스의 다중 인스턴스 제한은 메모리 카운터만으로 보장하지 않는다.

## 4. 실행 환경과 취소 계약

- [v] **R01** 일반 Node HTTP 서버에서 공용 처리 함수를 호출하는 어댑터를 제공한다. 개발용 `.env.local` 로딩과 운영용 환경변수 처리를 구분하고 서버 종료 시 진행 요청을 정리한다.
- [v] **R02** Vercel용 어댑터는 같은 공용 처리 함수를 호출하게 한다. Vercel SDK·전용 저장소·전용 작업 큐를 핵심 로직의 필수 의존성으로 넣지 않는다.
- [v] **R03** 첫 구현은 제한된 짧은 음성 조각별 HTTP 호출로 구성한다. 서버리스 응답 종료 후 메모리에서 장시간 작업이 계속될 것이라고 가정하지 않는다. 배포 시간 한도에 맞지 않으면 오류로 안내하며 공유 저장소·작업 큐는 별도 후속 설계로 다룬다.
- [v] **R04** 취소 시 가능한 범위에서 fetch·공급자 요청을 중단하고 늦은 응답은 클라이언트에서 무효화한다. 취소가 이미 수행된 공급자 처리나 과금을 되돌린다고 표시하지 않는다.

## 5. AI Gen의 로컬 음성 준비

- [v] **G01** 대상은 모달을 열 때의 선택 라인 전체로 고정한다. 블록 선택 개수와 관계없이 오디오가 있는 음소거되지 않은 영상이 있어야 하며 누락 원본·지원 불가 환경·새 라인 한도를 미리 안내한다.
- [v] **G02** `mediaLayout`을 이용해 합쳐진 블록·트림·띄엄띄엄 배치된 영상의 원본 구간과 프로젝트 절대 시간을 해석한다. 다른 라인·기존 자막·영상 사이 빈 공간은 분석 대상에 넣지 않는다.
- [v] **G03** 로컬 VAD로 발화 구간을 얻고, 구간별 음성을 PCM16 모노 WAV 등 공급자가 지원하는 형식으로 준비한다. 좌우 채널의 음성을 버리지 않도록 처리 방식을 명시한다. 긴 발화는 한도와 자막 가독성에 맞게 나누고 전체 길이 PCM을 만들지 않는다.
- [v] **G04** 구간 ID → 원본 참조·원본 in/out·프로젝트 시작/종료 시간 매핑을 AI Gen이 보관한다. 공용 전사 응답의 도착 순서에 의존하지 않으며 API에 프로젝트 시간을 추정하게 하지 않는다.
- [v] **G05** VAD·오디오 리더 등 저수준 처리는 기존 기능에 영향을 주지 않는 어댑터 뒤에서 재사용한다. Auto Cut·Auto Caption의 프리셋·상태·적용 로직은 변경하지 않고 AI Gen만의 작업 인스턴스를 사용한다.
- [v] **G06** 디코딩 공백은 절대 시간을 밀지 않고 처리한다. 정상적인 짧은 공백과 실제 디코더 실패를 구분하고 전사할 음성이 전혀 없으면 정상적인 결과 없음으로 표시한다.

## 6. AI Gen UI와 작업 수명

- [v] **U01** 타임라인의 AUTO CUT·AUTO CAPTION 옆에 아이콘이 있는 `AI Gen` 버튼을 추가한다. 다른 메뉴 구조는 유지하고 기존 모바일·태블릿 도구 스크롤에서도 접근 가능하게 한다.
- [v] **U02** AI Gen은 필요할 때 로딩하고 별도 오류 경계로 감싼다. 기능 조회·모듈 로딩·API 장애 때문에 편집기 전체가 종료되거나 일반 편집을 사용할 수 없게 만들지 않는다.
- [v] **U03** 모달에 대상 라인, 외부 음성 전송·과금 안내, 시작, 단계별 진행률, 성공/실패/남은 구간 수, 결과 텍스트 편집, 실패 구간 재시도, 완료·취소를 제공한다. 별도의 채팅·문장 정리 기능은 첫 구현에 필수로 추가하지 않는다.
- [v] **U04** 모달은 `idle → analyzing → transcribing → review → applying` 상태와 오류·취소 경로를 명시한다. 단계별 중복 실행과 완료 연타를 막고 상태가 바뀌어도 조작 가능한 취소 버튼을 제공한다. 최종 적용 중에는 취소를 잠근다.
- [v] **U05** 모달 진입 시 편집을 잠그고 프로젝트 스냅샷과 작업 ID를 고정한다. 모달 내부 상태는 프로젝트 저장·자동 복구·undo 이력에 넣지 않는다.
- [v] **U06** X·배경 클릭·Escape로 조용히 적용하거나 종료하지 않는다. 완료 또는 취소로 종료하고 포커스 가두기·원래 버튼으로 포커스 복귀·스크린리더 진행 안내를 제공한다.
- [v] **U07** 일부 요청 실패 시 성공 결과는 모달에만 보관하고 완료는 비활성화한다. 실패 구간만 재시도할 수 있으며 모든 요청이 정상 종료되면 완료를 허용한다. 정상적인 빈 전사는 실패로 취급하지 않는다.
- [v] **U08** 취소·모달 해제·페이지 종료 시 Worker·임시 음성 Blob·객체 URL·요청 큐를 해제한다. 작업 ID/generation이 다른 늦은 결과는 무시한다. 생성 중 결과를 프로젝트 자동 저장에 섞지 않는다.

## 7. 자막 결과와 최종 적용

- [v] **T01** 전사 텍스트를 대응하는 발화 구간에 연결하여 기본 자막 스타일의 초안을 만든다. 텍스트가 없는 구간은 생성하지 않으며 단어 단위 동기화를 제공한다고 표시하지 않는다.
- [v] **T02** 생성 계획은 순수 함수로 분리한다. 정수 마이크로초 `[start, end)` 계약, 영상 경계, 구간 중복·순서·라인 내 충돌·텍스트 길이·최대 블록 수를 검증한다. 구간 끝을 확장하거나 다른 블록을 밀지 않는다.
- [v] **T03** 완료 시 현재 프로젝트가 스냅샷과 같은지 확인하고 모든 결과를 먼저 검증한다. 새 라인 하나에 자막을 생성하되 기존 영상·자막·라인 순서는 보존한다. 생성 결과가 없으면 빈 라인이나 불필요한 undo 이력을 만들지 않는다.
- [v] **T04** `App.tsx`에 AI Gen 전용 최종 적용 경로를 두고 기존 `replaceTimeline` 명령과 입력 검증을 사용하여 한 번에 커밋한다. 모듈이 히스토리나 레지스트리를 직접 수정하지 않으며 실행 취소 한 번으로 복구되게 한다.
- [v] **T05** 적용 오류·프로젝트 변경·라인 한도 초과 시 모달에 오류를 표시하고 기존 프로젝트는 그대로 둔다. 성공이 확정된 뒤에만 모달을 닫고 새 자막 라인을 활성화한다.

## 8. 완료 기준과 인수인계

- [ ] **D01** 경계 계약·입력 검증·공급자 오류 변환·절대 시간 매핑·자막 생성 계획·원자적 적용·취소 후 늦은 응답에 결과 중심 검사를 추가한다. 별도 지시로 실행을 생략하면 미실행을 기록한다.
- [ ] **D02** 타입 검사·빌드와 변경 범위의 검사 명령을 실제 상태에 맞게 정리한다. 실제 공급자 요청 검증은 개인정보 없는 짧은 음성으로 수행하고 사용 계정·과금·전사 품질·시간 정밀도의 확인 여부를 구분한다. API 호출을 하지 않았다면 연결 성공으로 표시하지 않는다.
- [ ] **D03** 키 미설정·API 사용 불가·취소·부분 실패·재시도·적용 실패 후에도 기존 편집·Auto Cut·Auto Caption을 다시 사용할 수 있는지 확인하고 미확인 범위를 남긴다.
- [v] **D04** 일반 서버와 Vercel 배포의 명령·환경변수·자체 API 경로·플랫폼별 한도 차이를 문서화한다. 프런트 번들·소스맵·서비스 워커 캐시에 서버 비밀값이나 AI 음성 요청·전사 응답을 포함하지 않는다.
- [v] **D05** Plus 명시적 AI 실행 범위에 맞게 README·STRUCTURE·AGENTS의 정적 전용/외부 전송 금지 안내를 정합화한다. 기본 로컬 편집의 비전송 원칙은 유지하고 AI 실행 시 필요한 음성만 전송한다.

## 구현·확인 기록

- 공용 AI API 계층, DeepSeek 어댑터, 일반 서버·서버리스 진입점, AI Gen 모달·음성 준비·결과 적용 코드를 구현했다.
- `npm run build`의 고정 체크리스트 검사·프런트/서버 타입 검사·Vite 빌드가 통과했다. 단위 검사 소스는 추가했으나 실행하지 않았다.
- `npm run ai:check`로 사용자 데이터가 없는 합성 무음 WAV를 전송했다. 키 설정은 읽었지만 공급자 HTTP 402가 반환되어 성공 전사·음성 품질·시간 정밀도는 미확인이다. 잔액 확인 후 다시 연결 확인이 필요하다.
- D01은 취소 후 늦은 응답 등 전체 검사 항목을 아직 완성하지 않아 미체크다. D02는 실제 성공 응답 확인 전, D03은 편집기 오류 후 복귀 검증 전이므로 미체크로 남긴다.
- 사용자 요청으로 브라우저·실제 편집기 실행·단위 검사 실행·배포 검증은 생략했다. 운영 공유 요청량 제한 서비스는 별도 연결해야 하며 미설정 시 AI API가 503으로 차단된다.
- 실행 및 환경변수는 [AI Gen 실행·배포](./AI_GEN_DEPLOY.md)를 따른다. 체크는 코드 반영 완료 기준이며 모든 환경의 동작 보장을 의미하지 않는다.
