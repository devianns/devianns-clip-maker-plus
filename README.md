# Devianns Clip Maker Plus

로컬 영상으로 컷을 만들고, 한글 자막을 입혀 내보내는 브라우저 영상 편집기입니다. 기본 편집은 로컬에서 처리하고, Plus의 **AI Gen**을 실행할 때만 음성 구간을 자체 백엔드와 AI 공급자로 전송하여 실제 자막을 생성합니다. AI 기능에는 백엔드가 필요합니다.

Plus 실행은 `npm run dev`를 사용하며 웹과 AI 서버를 함께 시작합니다. 서버 전용 `.env.local`에 `DEEPSEEK_API_KEY`를 설정하세요. [실행·배포 안내](./docs/plus/AI_GEN_DEPLOY.md), [AI 구현 체크리스트](./docs/plus/clip_maker_plus_ai_checklist_v1.md)를 참고하세요. 이번 최소 API 확인에서는 공급자 HTTP 402가 반환되어 실제 전사 성공은 미확인입니다. 기존 아래 검증 기록은 기본 편집기의 과거 기록이며 Plus AI 기능의 검증 결과가 아닙니다.

현재 첫 편집기를 구현했습니다. 실제 Windows Edge에서 기능을 검증했으며, 공개 GitHub Pages 배포는 아직 수행하지 않았습니다. 기능별 완료 상태는 [고정 체크리스트](./CHECKLIST.md), 검사 환경과 결과는 [구현 기록](./IMPLEMENTATION.md)을 참고하세요.

## 실행

Node.js 24 LTS를 권장합니다. 최소 요구 버전은 Node.js 22.12입니다.

```sh
npm ci
npm run dev
```

기본 주소: **http://127.0.0.1:5173/**

Windows PowerShell에서 `npm.ps1` 실행 정책에 걸리면 같은 명령의 `npm`을 `npm.cmd`로 실행합니다. 이번 작업 환경에는 별도로 검증한 Node.js 24.22.3이 `.tools/node-v24.22.3-win-x64/`에 준비되어 있습니다. 이 개발 도구 폴더는 Git에 포함하지 않습니다.

```powershell
$env:PATH = "$PWD\.tools\node-v24.22.3-win-x64;$env:PATH"
npm.cmd run dev
```

## 편집 흐름

1. **미디어**에서 여러 영상을 임포트합니다. 썸네일·길이·원본 해상도를 확인합니다.
2. 에셋을 하단 **타임라인**으로 끌어놓습니다. 우클릭 메뉴나 `＋` 버튼으로도 삽입할 수 있습니다. 위치는 가까운 클립 경계에 맞춰집니다.
3. 시간 눈금이나 재생 위치 슬라이더를 움직여 탐색합니다. 상태줄의 초 입력으로 정확한 시점에 이동할 수도 있습니다.
4. `S`로 분할하고, 클립 핸들이나 오른쪽 원본 시작·끝 입력으로 트림합니다. 드래그나 이동 버튼으로 순서를 바꿉니다. 빈틈은 자동으로 닫힙니다.
5. **자막** 탭에서 한글 자막과 시간·스타일을 편집합니다. 자막은 프로젝트 시간에 고정되므로 클립 재배열 후 시간을 확인합니다.
6. **내보내기**에서 형식·해상도·FPS를 고른 뒤 렌더링하고 다운로드합니다.

영상과 원본 소리는 같은 클립 구간을 공유합니다. 자르기·이동·분할·삭제 때 함께 처리하며 독립 사운드 트랙 편집 UI는 제공하지 않습니다. 원본 에셋은 클립을 지워도 보관함에 남습니다.

| 단축키 | 동작 |
| --- | --- |
| Space | 재생 / 정지 |
| ← / → | 이전 / 다음 프레임 |
| S | 재생 위치에서 분할 |
| Delete / Backspace | 선택 클립 삭제 |
| Ctrl 또는 ⌘ + Z | 실행 취소 |
| Ctrl 또는 ⌘ + Shift + Z | 다시 실행 |

텍스트 입력 및 대화상자에서는 편집 단축키를 가로채지 않습니다. 드래그 작업에는 버튼과 숫자 입력 대안이 있습니다.

## 미리보기와 출력

- 미리보기는 1080p 기준 가로·세로 각각 50% 크기로 합성합니다. 가로 영상은 960×540입니다. 실제 처리 시간이 절반이라는 보장은 아닙니다.
- 출력은 미리보기 캔버스를 확대하지 않습니다. 내보내기 시작 시 최종 프로젝트를 복제하고 **원본 파일**에서 다시 읽어 렌더링합니다. 출력 중에는 편집을 잠급니다.
- 1080p / 720p / 480p와 30 / 45 / 60fps를 선택합니다. 가로 기준 1920×1080 / 1280×720 / 854×480입니다.
- 가로·세로·정사각 비율, contain/cover·배율·위치, 수동 자막을 미리보기와 출력에 공통 적용합니다.
- MP4(H.264/AAC)를 우선 제공하며 WebM(VP9 또는 VP8/Opus)도 지원 여부를 확인합니다. 환경에 따라 제공할 수 없는 설정은 이유를 표시합니다.
- 다운로드 방식은 예상/실제 256MiB 한도가 있습니다. 큰 출력은 지원 브라우저에서 **파일 직접 저장**을 선택합니다. 직접 저장은 파일 선택 권한이 필요합니다.

## 저장과 범위

프로젝트 JSON 저장/열기와 IndexedDB 자동 저장·복구를 제공합니다. **프로젝트에는 원본 영상이 포함되지 않습니다.** 새로고침이나 다른 기기에서 열 때 원본 파일을 재연결해야 할 수 있습니다. 원본 이름·크기·수정 시각·미디어 정보를 비교하므로 같은 파일을 보관하세요.

초기 범위는 데스크톱, SDR, 최대 5분 타임라인, 영상 트랙 하나와 결합 원본 오디오, 수동 자막입니다. 긴 원본을 5분 이상 그대로 삽입할 수 없습니다. 첫 비디오/오디오 트랙을 사용하고 지원하지 않는 오디오를 조용히 버리지 않습니다. HDR·다채널 오디오·DRM 입력, BGM·자동 자막·배속·전환·다중 영상 레이어는 현재 범위에 포함하지 않습니다. 모든 브라우저·기기에서 같은 코덱이나 성능을 보장하지 않습니다.

## 검사

```sh
npm run typecheck
npm test
npm run checklist:check
npm run build
```

브라우저 검사는 별도 터미널에서 `npm run dev`를 실행한 상태로 진행합니다.

```sh
npm run test:browser
npm run test:preview
```

첫 명령은 합성 영상·비프음을 만들고 실제 UI 및 9개 해상도/FPS 조합, 자막·A/V sync·취소·복구를 검사합니다. 두 번째 명령은 앞서 생성한 fixture와 `dist/`를 사용하며, 경로 보정이나 SPA fallback이 없는 임시 정적 서버에서 `/`와 `/devianns-clip-maker/`를 각각 검사합니다. Worker·폰트·오디오 출력·반응형 화면과 앱 파일 로딩 실패 안내까지 확인한 뒤 서버를 종료합니다.

Windows에서는 설치된 Edge를 사용합니다. 다른 OS는 Playwright Chromium을 준비하거나 `BROWSER_CHANNEL`을 지정하세요. 빠른 회귀 검사 시 `TEST_MATRIX=0`으로 9개 조합 반복만 생략할 수 있습니다. 검사 결과와 생성 영상은 Git에서 제외하는 `test-results/`에 저장합니다.

## 모듈 지도

| 경로 | 책임 |
| --- | --- |
| `src/editor/` | 도구막대, 에셋, 미리보기, 타임라인, 속성, 출력 창, 단축키 |
| `src/project/` | 데이터 모델, 시간 매핑, 편집 명령, undo/redo, JSON 검증 |
| `src/media/` | 로컬 파일 레지스트리, Mediabunny 입출력, 프레임 읽기 |
| `src/playback/` | 오디오 기준 시계, 재생·시킹, 최신 프레임 표시 |
| `src/render/` | 미리보기·출력 공통 영상/자막 합성, 로컬 폰트 |
| `src/audio/` | 결합 클립 오디오 구간, 블록 처리, 48kHz stereo 정규화 |
| `src/export/` | 출력 설정·지원 검사·예상 용량·작업 수명 |
| `src/workers/` | 별도 미리보기 디코딩과 원본 기반 영상/오디오 출력 |
| `src/storage/` | 프로젝트 JSON, IndexedDB 자동 저장/복구 |

UI는 미디어 엔진을 직접 다루지 않고 프로젝트 명령 및 재생/출력 서비스를 호출합니다. 유지보수 시 해당 모듈의 계약과 테스트를 먼저 확인하세요.

## 정적 배포

`npm run build` 결과인 `dist/`만 호스팅하면 됩니다. 서버 API나 COOP/COEP 설정은 필수 조건이 아닙니다. 저장소의 Pages 설정에서 **GitHub Actions**를 배포 소스로 선택하면 [workflow](.github/workflows/pages.yml)가 main push 시 검사·빌드·배포하도록 준비되어 있습니다. 실제 공개 사이트에 대한 수정 반영은 새 빌드의 재배포 후 확인해야 합니다.

기본 Vite `base`는 `./`입니다. 특정 저장소 이름에 고정하지 않아 같은 빌드가 루트 도메인과 저장소 하위 경로에서 동작합니다. 폰트도 Vite의 asset URL 처리로 Worker 위치를 기준으로 올바르게 읽습니다. 기본 구현은 runtime CDN과 서버 rewrite에 의존하지 않습니다. 소스 루트의 `index.html`은 Vite 개발 진입점이므로 빌드 없이 그대로 배포하는 파일이 아닙니다.
